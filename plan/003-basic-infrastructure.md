# Plan: Basic infrastructure for building and deploying the todo app
Spec: [spec/003-basic-infrastructure.md](../spec/003-basic-infrastructure.md). Intent: [intent/003-basic-infrastructure.md](../intent/003-basic-infrastructure.md). Status: approved.

## Approach
Hand-scaffold the Vite `react-ts` layout in the repo root (the `create-vite` CLI is interactive and wants an empty dir), then add Vitest + React Testing Library + jsdom, ESLint flat config with `typescript-eslint`, `eslint-plugin-react-hooks` and `eslint-plugin-jsx-a11y`. One workflow `.github/workflows/ci.yml` has a `ci` job (lint, typecheck, test, build) and a `deploy` job that needs `ci` and only runs on push to `main`, publishing `dist/` via the official Pages actions. Vite `base` is `/AnthropicSDLCExample/` (the repo name in `git remote`; the local folder name differs, so do not derive it from the folder). One job file keeps "deploy only after checks pass" structural rather than relying on cross-workflow triggers. Versions: install current latest from npm and let `package-lock.json` pin them; Node 22 in CI (matches local v22).

## Order of work
Each step leaves the repo green; run the relevant script after each.
1. **Branch and plan.** `git switch -c build/003-basic-infrastructure`; save this plan as `plan/003-basic-infrastructure.md` with `Status: approved`; commit it alone. (Plan-sync hook only applies once `plan/` exists, so later implementation commits must touch the plan or carry `Plan-Checked: yes`.)
2. **Skeleton (Req 1).** `npm init`-style `package.json`; `npm i react react-dom`; `npm i -D vite @vitejs/plugin-react typescript @types/react @types/react-dom`; add config files, `index.html`, `src/main.tsx`, `src/App.tsx`. Verify `npm run build` produces `dist/` and `npm run typecheck` passes; deliberately add a type error to confirm it fails, then remove it.
3. **Tests (Req 2).** `npm i -D vitest jsdom @testing-library/react @testing-library/jest-dom @testing-library/user-event`; add `vite.config.ts` test block, setup file, smoke test. Verify `npm test` passes and exits non-zero when the assertion is broken.
4. **Lint (Req 3).** `npm i -D eslint @eslint/js typescript-eslint eslint-plugin-react-hooks eslint-plugin-jsx-a11y globals`; add `eslint.config.js`. Verify `npm run lint` passes, and fails when an unlabelled `<input />` is added temporarily.
5. **README (Req 6, 9).** Write docs as listed above.
6. **CI and deploy (Req 4, 5, 7).** `ci.yml`:
   - `on: pull_request` and `push: branches: [main]`; top-level `permissions: contents: read`.
   - Job `ci` (name `ci`, the required check): `actions/checkout`, `actions/setup-node` (node 22, npm cache), `npm ci`, `npm run lint`, `typecheck`, `test`, `build`; on push to `main` only, `actions/configure-pages` + `actions/upload-pages-artifact` with `path: dist`. No secrets.
   - Job `deploy`: `needs: ci`, `if: github.event_name == 'push' && github.ref == 'refs/heads/main'`, `permissions: pages: write, id-token: write`, `environment: github-pages`, `actions/deploy-pages`. `concurrency: group: pages, cancel-in-progress: false` on deploy.
   - Pin actions to current major versions (check latest majors at time of writing).
7. **Push and verify CI (needs human approval to push).** Open a PR; confirm `ci` runs green and `deploy` is skipped.
8. **Manual one-offs (Req 5, 8; by hand, owner).** Repo Settings → Pages → Source: "GitHub Actions". Settings → Rules (or Branches) → protect `main`, require status check `ci`, with the repo admin allowed to bypass. Merge the PR, confirm deploy runs and the Pages URL loads with assets.

Note: the merge gate (step 8) should be enabled after the first green CI run so the `ci` check name is selectable.

## Tests
- `src/App.test.tsx` (Req 2): renders `<App />`, asserts `screen.getByRole('heading', { name: 'Todo app' })` is present. Using role queries proves Testing Library accessible queries work.
- Req 1: manual/scripted checks in step 2 (`dist/index.html` exists; asset URLs in it start with `/AnthropicSDLCExample/`; type-error fails); CI `build` step covers it thereafter.
- Req 3: temporary unlabelled input fails `npm run lint` (step 4); reverted.
- Req 4: PR run shows all four steps and fails if any breaks (spot-check by one deliberate failing PR commit, then revert, optional).
- Req 5, 6: after merge, deploy job succeeds and `https://amjones-scottlogic.github.io/AnthropicSDLCExample/` shows the heading with CSS/JS loading (no 404s in the network panel); a PR run shows `deploy` skipped.
- Req 7: `grep -rE "https?://" dist` shows no external URLs other than inert namespace strings (e.g. `w3.org`); no CDN/font links in `index.html`; no server code in repo.
- Req 8: with protection on, a PR with a failing check cannot be merged by the normal path; admin bypass is available and visible.
- Done when: `npm ci && npm run lint && npm run typecheck && npm test && npm run build` is green locally and in CI, and the Pages site is live.

## Risks
- **Highest risk: step 6/8, Pages deployment and base path.** A wrong `base` or Pages source setting yields a blank page with 404 assets. Contained by verifying `dist/index.html` asset paths locally (`npm run build && npx vite preview`, which serves under the base) before pushing, and by checking the live URL after the first merge.
- **Repo name drift.** `base` and the documented URL hard-code `AnthropicSDLCExample`. Renaming the repo breaks both and strands localStorage data (spec's flagged concern). Mitigation: README note; not preventable.
- **Merge gate lock-out.** Required check name must exactly match the job name `ci`; if it never reports, merges are blocked. Mitigation: admin bypass, enable the rule after the first green run.
- **Dependency drift / peer conflicts** (ESLint plugin versions vs ESLint major). Mitigation: install latest compatible and run `npm ci` fresh to confirm the lockfile is consistent.
- **Plan-sync hook** blocks commits touching implementation files unless plan changed or `Plan-Checked: yes` trailer is present; use the trailer when the plan still matches.
- Pushes require human approval (`push-gate`); nothing is pushed by the implementation without it.

## Alternatives rejected
- **Separate `deploy.yml` workflow on `workflow_run`:** more moving parts and weaker "only after checks pass" guarantee than `needs:` in one workflow.
- **Run `npm create vite@latest`:** interactive, requires an empty directory, and would generate extra template files (demo CSS, assets, logos) that we would then delete. Hand-scaffolding is smaller.
- **Jest instead of Vitest:** second build/transform pipeline; the spec chose Vitest.
- **`gh-pages` branch deploy:** the spec chose the "GitHub Actions" Pages source with the official actions.
- **Setting `base` via env var/CI-only:** adds divergence between local and CI builds; a fixed constant is simpler given the URL is fixed by spec.
